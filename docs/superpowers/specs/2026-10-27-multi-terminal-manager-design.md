# 多终端管理

用户已选择「终端列表＋快捷命令」：终端首页上方列出终端，下方保留快捷命令；进入后可切换终端。沿用现有灵动岛颜色、布局和快捷键规则，不增加新的工具栏入口。

## 用户结果

- 同时创建和运行至少三个独立的 WorkIsland 终端。列表显示名称、工作目录、运行/退出状态，可进入、新建、重命名、关闭具体终端。
- 快捷命令新建自己的终端，避免把新命令输入另一个正在运行的 Agent。
- 返回列表、切换插件、收起灵动岛不会终止进程；关闭某项只关闭该项，停止全部仅用于关闭终端功能或退出应用。
- 已访问的终端保留 xterm 实例和画面、滚动位置、未提交输入；后台输出与前台终端隔离。首次打开按终端 ID 获取缓存，并通过递增序号去除订阅与快照重叠数据。
- 进程自然退出后保留列表、退出码和输出，可以重启同一项或移除；所有命令及终端内容仅在本机处理。

## 实现决定

复用 node-pty、xterm 和既有 IPC；仅增加官方 FitAddon，通过公开接口计算尺寸，替代私有内部访问。TerminalService 从单 PTY 改为按稳定 ID 管理的 Map，兼容既有 start/input/resize/restart/stop 调用，新增 create/select/close/rename。输入、输出、尺寸和关闭携带 ID，未知 ID 失败而不回退到其他终端。每项输出缓存有界、总数量有界，单次大输出分块而不截断。

外部终端不能无损接管到新 PTY。macOS 用户主动查找外部 Terminal/iTerm 会话，按宿主稳定定位并跳回原窗口；显示宿主及操作能力。仅提供经适配器确认能精确关闭的关闭操作，不拿关闭整窗或模糊 PID 替代关闭标签页。拒绝自动化授权不影响内部终端。其他宿主与 tmux 的通用接管不作为本次完整支持的承诺。产品内部新建、进入、关闭是完整验收范围，符合用户明确允许的识别范围回退。

## 验收证据

先验证三个 fake PTY 的独立输入/输出/退出/关闭和旧实例迟到事件，再运行真实 node-pty 与实际 Electron/xterm：创建三个终端，各写不同标识；后台持续写入时切换；保留半行输入和滚动；关闭中间项，另两项可继续输入；关闭当前项有明确回退；快捷命令创建独立项；键盘 Enter/方向/Escape 不被全局快捷键抢占；禁用与退出清理全部自建 PTY。

实际界面验证空状态、三项、多项可滚动、退出/重启、长名称和目录、窄屏/小窗口、深色产品主题、错误恢复。外部真实宿主与权限行为单独记录，不用 mock 证明真实第三方控制。正式分发须另走版本发布流程，本次不自动发布新版。
