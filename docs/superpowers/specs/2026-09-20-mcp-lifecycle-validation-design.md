# WorkIsland MCP 生命周期验证设计

## 目标

确认 Codex 等客户端断开后，WorkIsland MCP stdio 子进程能够正常退出；只修复被实测证明的孤儿进程问题，不改变智能体配置 WorkIsland 的能力。

## 产品边界

- 保留现有 stdio MCP 接入方式。
- 保留全部工具名称、输入结构、输出结构和权限语义。
- 保留读取能力、诊断、设置修改、撤销、显示形态切换、打开设置和会话定位功能。
- 不改成 HTTP 服务，不增加常驻端口，不合并不同客户端的权限上下文。
- 客户端仍然为每条活跃 MCP 连接拥有一个进程；本阶段只确保连接结束后没有无主残留。

## 实现策略

先建立可重复的生命周期基准：启动 MCP、完成 initialize/list tools、关闭 stdin 或断开客户端，记录退出状态、耗时和残留进程。连续执行 50 次并检查进程数。

如果现有实现全部自然退出，则保留产品代码，只提交基准探针、测试和报告。如果出现残留，则在 stdio 入口增加有界清理：stdin 结束、传输关闭或不可恢复错误时关闭 server，并让进程自然退出。不得通过固定空闲超时杀掉仍然连接的客户端。

## 错误处理

- 初始化失败返回 MCP 协议错误并退出，不进入无限等待。
- 客户端仍连接时不因暂时没有工具调用而退出。
- WorkIsland 主程序不可用时继续返回现有结构化 UNAVAILABLE 错误，不改变连接生命周期。

## 验证

- 现有 MCP 工具契约测试全部通过。
- 逐个调用读工具和写工具的现有转发测试通过。
- 50 次连接与断开后，测试创建的 MCP 进程全部退出。
- 记录单进程 RSS 与全部外部 MCP 合计，但不把客户端仍在使用的进程误判为泄漏。

## 完成标准

只有确认无孤儿进程且所有工具行为一致，才把该方向标记为完成。没有泄漏时，不为了减少进程数重写协议。
