# WorkIsland MCP 产品助手重设计

## 背景

现有 MCP 已具备安全的本机连接、设置白名单、会话状态读取、设置变更提示和撤销能力，但产品体验把“修改设置”放在首位。用户自己打开设置通常更直接；同时，智能体无法可靠回答“灵动岛有哪些扩展功能”“支持哪些智能体”“为什么某项功能没有出现”等更有价值的问题。

本次重设计将 MCP 定位为 **WorkIsland 产品助手**：首先帮助智能体理解 WorkIsland、观察 WorkIsland 已监控的智能体状态、解释异常并导航到正确位置；设置修改只是用户明确要求后的辅助能力。

## 目标

1. 用户可以通过已连接的智能体准确了解 WorkIsland 的完整功能，而不是让模型从设置名称推测。
2. 用户可以查询 WorkIsland 已监控到的本机智能体会话状态和待处理事项。
3. 用户可以了解支持的智能体、接入健康状态和可用能力。
4. 用户可以诊断常见的显示、接入和功能可用性问题。
5. 用户明确要求时，智能体仍可读取、修改和撤销安全设置。
6. 设置页面清楚解释 MCP 的价值，同时保持较低的信息层级和视觉权重。

## 非目标

- 不扫描或宣称掌握电脑上的所有进程和智能体。
- 不读取提示词、回答、项目路径、终端标识、PID 或原始 Hook 数据。
- 不允许执行任意终端命令、修改任意文件或绕过审批。
- 不让智能体批准请求、回答其他智能体的问题、删除会话或结束进程。
- 不把 MCP 提升为 WorkIsland 的核心导航入口。

## 设置中的命名与位置

- 导航名称：`MCP`
- 页面标题：`MCP 服务`
- 总开关：`启用 WorkIsland MCP`
- 客户端区域：`连接智能体`
- 原“智能体控制”文案、变量的用户可见名称全部移除。
- MCP 位于设置导航的**倒数第二位**，仅高于“关于”。它不能出现在第 3 位或第 4 位，也不与工作台、智能体接入等核心设置竞争视觉优先级。

内部兼容字段可以暂时保留，避免迁移破坏已有用户配置；但界面、文档、辅助功能标签和错误提示统一使用 MCP。

## 核心体验

### 1. 产品功能发现

提供由代码维护的结构化功能目录。每项能力至少包含：

- 稳定 ID、名称、分类和一句话说明
- 适用平台和当前是否可用
- 当前是否启用
- 如何触发或使用
- 相关设置键与设置页面
- 数据来源、联网行为和隐私说明
- 依赖条件及不可用时的常见原因

首批分类：智能体监控、媒体、性能、文件与分享、剪贴板、终端、用量、通知与声音、显示与桌宠、快捷操作。

这样智能体可以回答“灵动岛有哪些扩展功能”“文件架和剪贴板有什么区别”“哪些功能需要联网”，而不是从 19 个可写设置中猜测产品结构。

### 2. 智能体监控状态

MCP 返回的是 **WorkIsland 已观察到并仍在展示范围内的会话**，不是全系统进程清单。每个会话只暴露：

- 临时、不透明的公开 ID
- 智能体名称
- 标准化阶段：运行中、已完成、出错、等待审批、等待回答等
- 最近活动时间
- 是否需要用户处理
- 是否能够跳回原会话

允许用户询问“哪些智能体正在运行”“哪个任务在等我”“最近哪个任务完成了”，并在明确要求时跳回可聚焦的会话。

### 3. 智能体接入状态

复用现有 Hook 健康检查与真实事件验证，向 MCP 暴露脱敏后的接入信息：

- 支持的智能体名称
- 是否启用、是否安装
- 是否验证过真实生命周期事件
- 能力范围：实时状态、工具活动、完成事件、审批、提问和跳转
- 必要时给出修复建议或打开对应设置入口

“配置已写入”与“真实可用”必须分开表达，不能把配置存在称为连接成功。

### 4. 只读诊断

诊断能力接收有限的功能或智能体标识，不接受任意路径、命令或 URL。首批覆盖：

- 智能体未出现在灵动岛
- 会话为何已消失或不再可见
- 媒体卡片没有出现
- 性能监控或进程详情没有出现
- 文件架、剪贴板、终端或用量模块没有出现
- 某项功能因设置、平台或依赖条件不可用

诊断结果包含：观察到的状态、可能原因、用户可执行的下一步和相关设置页面。诊断默认只读，不自动修改设置。

### 5. 设置与操作

保留设置描述、读取、原子修改和撤销。设置修改必须继续满足：

- 仅允许显式白名单键和值域
- 用户提出明确修改意图后才调用
- 每次修改在灵动岛或桌宠上展示客户端、旧值和新值
- 支持无冲突撤销
- 主开关关闭后立即拒绝所有 MCP 调用

保留打开设置、切换显示载体和聚焦会话。操作能力在工具说明中明确标为动作，不与只读发现、监控和诊断混淆。

## MCP 工具面

建议工具如下：

| 工具 | 类型 | 用途 |
| --- | --- | --- |
| `list_capabilities` | 只读 | 按分类列出完整产品功能及当前可用状态 |
| `get_capability` | 只读 | 返回一个功能的用法、隐私、依赖与相关设置 |
| `list_integrations` | 只读 | 列出支持的智能体和脱敏接入健康状态 |
| `list_active_sessions` | 只读 | 列出 WorkIsland 当前可见的脱敏会话状态 |
| `diagnose` | 只读 | 诊断白名单内的功能或接入问题 |
| `get_product_state` | 只读 | 返回当前显示载体、模块状态和待处理摘要 |
| `describe_settings` | 只读 | 描述允许读取或修改的复杂设置 |
| `get_settings` | 只读 | 读取允许设置的当前值 |
| `update_settings` | 动作 | 原子修改明确白名单内的设置 |
| `undo_settings_change` | 动作 | 撤销无冲突的近期 MCP 修改 |
| `focus_session` | 动作 | 跳回仍可聚焦的公开会话 |
| `open_settings` | 动作 | 打开白名单内的设置页 |
| `set_display_surface` | 动作 | 在灵动岛和桌宠之间切换 |

可以保留旧工具名的内部兼容映射，但面向模型的描述必须把产品发现、状态和诊断放在前面，把设置修改放在后面。

## 设置页面信息架构

页面从上到下：

1. **MCP 服务**：总开关、简短价值说明和当前服务状态。
2. **连接智能体**：Codex 一键连接状态，以及受支持客户端的边界说明。
3. **你可以这样问**：展示产品发现、会话状态、诊断和明确设置操作的示例问题。
4. **权限与隐私**：用易懂语言说明可以读取什么、不能读取什么、哪些操作会改变设置。
5. **最近活动**：精简显示客户端、工具、结果和设置键，不保存内容。
6. **高级设置**：折叠放置手动配置、配置路径、复制和移除入口。

页面不默认铺开 TOML，不使用开发者控制台式布局，也不把 MCP 包装成所有用户都必须开启的核心功能。

## 数据与安全边界

- 继续使用当前用户的 Unix Socket 或 Windows 命名管道，不监听 TCP。
- 所有能力必须经过主进程总开关和命令白名单。
- 功能目录只包含产品元数据和当前布尔/枚举状态，不包含用户内容。
- 接入健康信息不返回本机路径、配置内容或原始错误堆栈。
- 会话使用临时公开 ID；会话结束后映射失效。
- 审计日志字段固定、数量有上限，不保存提示词和响应。

## 错误与表达

- 区分“未启用 MCP”“WorkIsland 未运行”“客户端仅配置未调用”“集成未安装”“尚未收到真实事件”和“当前没有可见会话”。
- 不使用“电脑上没有运行该智能体”这种超出观察范围的结论，改为“WorkIsland 当前没有观察到可见会话”。
- 诊断建议必须给出证据来源，无法确定时明确标为可能原因。

## 验证标准

### 自动化

- 功能目录覆盖所有设置页核心模块，且 ID、平台和相关设置合法。
- 只读工具不能触发设置写入或窗口动作。
- 会话、接入与诊断返回值通过隐私字段扫描。
- MCP 导航在设置中始终为倒数第二项。
- 所有现有设置白名单、撤销、审计、Socket/命名管道测试继续通过。
- macOS、Windows x64 和源码契约 CI 全部通过。

### 真实体验

使用全新 Codex 会话逐字测试：

1. “灵动岛有哪些扩展功能？”
2. “电脑上有哪些被 WorkIsland 监控的智能体正在运行？”
3. “现在有没有智能体在等我处理？”
4. “WorkIsland 支持哪些智能体，哪些已经连接成功？”
5. “为什么性能监控没有显示进程详情？”
6. “文件架和剪贴板历史有什么区别？”
7. “把完成提醒改成 8 秒。”

前六项必须基于 MCP 返回的数据回答，不读取仓库文件；第七项必须出现可撤销的设置变更提示。

## Git 与交付门禁

1. 通过独立回退 PR 从 `main` 移除当前未经验收的 MCP 实现，不改写历史。
2. 重新打开 Issue #11，反映功能仍在设计和开发中。
3. 在 `codex/mcp-product-redesign` 上维护新的 Draft PR。
4. 开发、CI、本机安装和真实 Codex 验收全部在 Draft PR 阶段完成。
5. 未得到产品所有者明确的“可以合并”指令前，Draft PR 不得转为 Ready，也不得合并。
