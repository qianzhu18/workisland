# WorkIsland 应用中英文适配设计

**关联 Issue：** #110 `feat(i18n): 应用内界面中英双语框架（B-12）`

**状态：** 用户已确认，进入实现

## 1. 目标

WorkIsland 提供完整的简体中文和英文应用体验。全新安装与历史安装默认跟随操作系统语言；用户可在设置中选择“跟随系统”“简体中文”或“English”。切换后，所有已打开的 WorkIsland 界面立即更新，不重启应用，也不破坏终端、会话或当前工具状态。

本次同时把国际化变成构建契约：两份语言资源必须拥有完全相同的 key；面向用户的界面代码不得绕开翻译层新增文案，否则 `npm run check` 直接失败。

## 2. 当前问题

仓库已有一个未完成的语言外壳：

- 设置中会写入旧的 `locale` 字段；
- 主进程和 preload 已暴露语言 IPC；
- 部分 renderer 组件使用 `i18n.k...`，但它只返回中文兜底；
- 中英文翻译资源都是空对象；
- 设置页、通知、系统对话框、Doctor、引导页和多个工具面板仍直接写死中文。

因此这不是批量替换文案，而是先建立唯一可信的运行时语言服务，再把所有正式产品界面迁移到它上面。

## 3. 方案比较

### 方案 A：只跟随系统

应用启动时读取系统语言，系统语言改变后要求重启。实现最少，但双语用户无法单独控制 WorkIsland，也不符合 Issue #110 已确定的手动覆盖方向。

### 方案 B：系统默认 + 应用内即时覆盖（采用）

以系统语言为默认，持久化三态语言偏好，把语言变化广播给所有窗口，并用 CI 校验共享语言资源。它既符合 macOS 的使用习惯，也适用于 Windows，并允许用户让 WorkIsland 使用不同于系统的语言。

### 方案 C：引入大型第三方 i18n 运行时

使用 i18next 一类完整框架。它具备更多插件能力，但当前 WorkIsland 没有常规前端打包器，第一阶段只需要语言解析、扁平资源、参数插值和变化订阅；额外依赖会扩大运行时和打包复杂度，因此不采用。

## 4. 语言策略

### 4.1 设置值

新增 `languagePreference`，只允许：

- `system`：默认值；
- `zh-CN`：明确使用简体中文；
- `en`：明确使用英文。

旧 `locale` 是程序自动写入的，并不能证明用户做过明确选择。设置迁移时删除它，历史用户同样回到“跟随系统”。

### 4.2 系统语言解析

Electron ready 后读取 `app.getPreferredSystemLanguages()`，按系统给出的优先顺序处理：

1. `zh`、`zh-CN`、`zh-Hans*` → `zh-CN`；
2. `en`、`en-*` → `en`；
3. `zh-Hant*` 不擅自当作简体中文，继续查看下一项系统偏好；
4. 没有匹配语言时回退英文。

界面语言和地区格式分开：文案使用解析后的应用语言；时间、日期和数字仍遵循操作系统地区格式，除非某个产品场景明确要求固定格式。

### 4.3 macOS 声明

安装包在 bundle metadata 中声明 `en` 与 `zh-Hans`，并把英文作为 development fallback。macOS 因此能够识别应用支持的语言，并兼容系统的单应用语言偏好。

## 5. 架构

### 5.1 单一语言资源

创建两份语义化、扁平的资源文件：

- `src/locales/zh-CN.json`
- `src/locales/en.json`

key 表达产品含义，不再使用 `k123456` 这类生成编号。例如：

```json
{
  "common.actions.cancel": "取消",
  "island.terminal.fullTitle": "完整终端",
  "settings.general.language.title": "语言",
  "notifications.update.available.title": "WorkIsland 有新版本"
}
```

两份资源的 key 必须完全一致。参数使用 `{count}`、`{agent}` 这样的具名占位符。产品名、命令、路径、用户内容、Agent 原文和终端输出保持原样，不经过翻译。

### 5.2 共享语言核心

无第三方依赖的共享模块负责：

- 支持语言与偏好常量；
- 设置值校验和旧字段迁移；
- 按顺序解析系统语言；
- 语言资源查找和具名参数插值；
- 意外缺 key 时回退英文。

缺 key 在测试和 CI 中属于失败。运行时回退只用于避免本地损坏构建把关键按钮显示为空。

### 5.3 主进程语言服务

主进程持有唯一权威的 `languagePreference` 与 `resolvedLocale`，因为只有它能读取 Electron 系统语言 API，并负责系统通知、菜单和对话框。

语言服务提供：

- 当前偏好与最终语言；
- 供通知、菜单、对话框和用户可见错误使用的同步翻译函数；
- 供 renderer 初始化的 `{ preference, locale, messages }` 快照；
- 保存偏好、重新解析语言、重建原生菜单/托盘并广播变化的更新方法。

处于 `system` 时，应用每次重新激活都会检查系统语言。若最终语言变化，就向所有窗口广播；因此系统语言变更在可检测时下次激活生效，最迟下次启动生效。

### 5.4 Renderer 语言状态

每个 renderer 在首次有效渲染前载入语言快照，并订阅语言变化。收到更新后替换内存资源，再通过现有根节点或 `renderPage()` 触发完整重绘，不 reload 页面。

这一点对 WorkIsland 很重要：语言切换不能重建 Island 窗口、卸载 xterm、重启 PTY、清空问答草稿或重置当前工具。

Island 等 React 界面在根节点维护 locale revision，以此触发组件树重绘；原生 Settings 页面继续复用现有 `renderPage()`；Welcome、Pet、Pet Panel 和 Debug 使用相同的初始化与订阅契约。

### 5.5 设置入口

在“通用”设置顶部附近增加“语言”选择：

- 跟随系统 / Follow System
- 简体中文
- English

语言名称保持自解释。切换后立即保存并同步全部打开窗口，不显示重启提示。

## 6. 本次覆盖范围

首个双语版本覆盖：

1. Island 胶囊、会话卡片、审批、提问、计划确认、完成态、工具栏、文件架、剪贴板、终端、媒体、性能、用量与更新界面。
2. 完整设置应用，包括空状态、错误、确认框、无障碍名称、反馈、MCP、远程接入、模板、遥测、更新和关于。
3. Welcome/首次引导、Pet、Pet Panel 与用户可见的 Debug Playground 文案。
4. 主进程系统通知、更新提示、文件/目录对话框、权限引导、macOS 应用菜单、Windows 托盘菜单和会呈现给用户的错误。
5. Doctor 命令的标题、诊断结果、修复建议和总结。

开发日志、源码注释、协议标识、测试 fixture、第三方 payload，以及必须原样展示的 shell/Agent/用户内容不属于翻译对象。

## 7. 防止未来队友破坏规则

新增 `npm run check:i18n` 并接入 `npm run check`。以下情况直接失败：

- 任一语言资源无法解析或为空；
- 两份资源的 key 集合不同；
- 同一个 key 的具名占位符不一致；
- 使用未支持的语言或偏好值；
- 指定的产品展示文件出现直接写入的中文 UI 文案；
- 常见 UI 构造方式中出现未通过翻译函数生成的 label、description、placeholder、title、确认文案或无障碍名称。

扫描器只覆盖产品展示边界，不扫描所有源码文本，避免中文注释和内部诊断造成误报。新增 `docs/I18N.md` 并更新 `CONTRIBUTING.md`，写清 key 命名、参数插值、语言选择、检查命令和新增语言流程。

以后开发新功能只有一条规则：同一次修改向两份资源加入同一个语义 key，在展示边界调用统一翻译函数，并通过 `npm run check`。

## 8. 异常与回退

- 非法持久化偏好统一归一化为 `system`；
- 无法读取系统语言时使用英文，并只记录一次开发日志；
- renderer 暂时拿不到语言快照时使用随包英文资源，界面仍可操作；
- 未知 key 优先返回英文值，开发环境额外记录诊断；
- 用户数据和外部 Agent 内容永远不进入翻译查找；
- 语言变化只修改 `languagePreference` 和展示内容，不改变会话、终端或业务服务状态。

## 9. 验证

### 自动化验证

- 系统语言解析测试：优先顺序、显式覆盖、未知语言、`zh-Hans` 和 `zh-Hant`。
- 设置迁移测试：旧 `locale` 不会变成错误的手动覆盖。
- 翻译测试：查 key、参数插值、缺参数和英文回退。
- IPC/服务测试：偏好保存并广播，renderer 不 reload。
- 全量 key 一致性和占位符一致性测试。
- 源码守卫 fixture：硬编码 UI 文案会失败，允许的内部文本会通过。
- 完整 `npm run check` 通过。

### 安装版验证

构建并安装 macOS 应用后验证：

1. 中文系统偏好首次启动显示全量简体中文；
2. 英文系统偏好首次启动显示全量英文；
3. 设置内可执行 中文 → English → 跟随系统，且无需重启；
4. Island、设置、引导/Pet、原生菜单、对话框和通知语言一致；
5. 完整终端及其 PTY 在语言切换前后保持不变；
6. app bundle 正确声明 `en` 与 `zh-Hans`；
7. `npm run check`、DMG 校验、签名校验、安装包与已安装 `app.asar` 一致性和 CI 全部通过。

## 10. 交付边界

本次只发布 `zh-CN` 与 `en`。语言 ID、共享资源和 IPC 均按标准 locale 设计，未来增加 `zh-Hant` 或其他语言时不需要修改业务组件。翻译 SaaS、运行时机器翻译、RTL 布局、官网本地化和双语 Release Notes 不在本 Issue 范围内。
