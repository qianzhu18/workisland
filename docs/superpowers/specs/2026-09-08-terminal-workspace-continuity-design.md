# 智能终端工作区连续性设计

## 背景

WorkIsland 的 PTY 已经是持久会话，但完整终端的界面状态仍属于 `TerminalPanel` 的局部状态。智能体通知会把活动模块强制切到首页，终端组件随之卸载；用户再次进入终端时，组件重新以快捷命令首页启动。这让“收起灵动岛”和“收到通知”产生了退出终端的副作用。

## 产品原则

终端是持续工作的工作区，不是一次性弹窗：

- 收起灵动岛只改变可见性，不改变工作区。
- 智能体通知只表达关注状态，不抢占用户正在操作的页面。
- 只有用户主动执行导航或退出动作，才改变终端页面状态。

## 交互规则

### 首次进入

- 尚未进入完整终端时，继续显示快捷命令与“进入完整终端”。
- 现有空状态、快捷命令和设置入口保持不变。

### 完整终端连续性

- 用户进入完整终端后，点击岛外、窗口失焦或灵动岛收起都不得退出完整终端。
- 如果收起前当前页面就是完整终端，再次展开灵动岛时直接恢复完整终端。
- 用户主动切换到智能体主页或其他工具后，终端在后台保持挂载；再次选择终端仍回到完整终端。
- 用户点击“返回快捷命令”时，才结束完整终端界面状态。
- PTY 退出时仍显示完整终端及“重新启动终端”，不自动返回快捷命令。
- 应用退出或终端功能被关闭时允许清理界面状态；本次不把状态持久化到磁盘。

### 智能体通知

- 普通通知、完成通知和需要操作的通知均不得自动修改当前工具模块。
- 通知仍可按现有策略展开灵动岛。
- 智能体主页按钮继续承担未读或待操作提示；用户主动点击后再进入智能体主页。
- 本次沿用现有通知视觉，不新增独立通知中心或新的浮层样式。

### 重新展开设置

- `toolboxReopenMode` 继续决定普通工具页在收起后重新展开时首先显示智能体主页还是上次工具。
- 完整终端属于正在持续的工作区：当它是收起前的当前页面时，恢复优先级高于该通用偏好。用户已经主动切到其他工具后再收起，则不强制跳回终端。

## 技术设计

### 状态边界

将状态分为两类：

- 展示状态：灵动岛展开、收起、失焦和通知展示。
- 工作区状态：当前工具、终端处于快捷模式还是完整模式、xterm 实例及其视口。

展示状态变化不得重置工作区状态。

### 终端组件生命周期

- `TerminalPanel` 在终端功能启用期间持续挂载，通过可见状态控制显示与隐藏。
- xterm 只在第一次进入完整终端时创建；切换工具或收起灵动岛时不销毁。
- 终端再次可见时重新执行尺寸同步并恢复焦点。
- `setTerminalInteractive(true)` 只在灵动岛已展开、终端模块可见且处于完整模式时启用；隐藏时必须恢复 Island 全局快捷键，但不能销毁 xterm。

### 模块选择策略

- 去掉“智能体需要关注时强制把活动模块改为 `agent`”的导航副作用。
- 将“收起前是否正在使用完整终端”作为明确的工作区状态传递给重新展开策略。
- 用户点击工具栏属于显式导航，仍可以立即切换模块。

## 方案对比

1. 只把重新展开偏好改成“上次工具”：改动小，但仍会卸载终端并丢失完整模式，不采用。
2. 保留终端工作区并让通知不抢占：同时解决导航和组件生命周期问题，采用。
3. 把终端拆成独立窗口：隔离彻底，但超出本次问题范围并削弱岛内工作流，不采用。

## 验收标准

- 完整终端中输入未执行的半条命令，点击岛外再展开后，仍显示完整终端和原输入上下文。
- 完整终端可见时收到普通、完成或待操作通知，当前页面不被切到智能体主页。
- 主动切换到其他工具再返回终端，仍是同一个完整终端实例。
- 点击“返回快捷命令”后再离开和返回，保持快捷命令首页。
- PTY 退出后停留在完整终端并提供重启按钮。
- 终端隐藏期间 `Esc`、`Up`、`Down`、`Return` 等 Island 快捷键恢复；终端重新可见后键盘输入重新归 xterm。

## 测试范围

- 为工作区状态模型添加单元测试，覆盖通知、收起、显式导航和显式返回快捷命令。
- 为 `TerminalPanel` 添加源码契约测试，保证 xterm 生命周期与 `terminalInteractive` 可见性分离。
- 运行完整 `npm run check`。
- 构建并安装 macOS 预览包，在真实 WorkIsland 中按验收标准走通终端恢复流程。

## 非目标

- 不跨应用重启恢复 PTY 或终端界面。
- 不新增多终端、多标签或终端会话管理。
- 不改变快捷命令的配置方式。
- 不重新设计通知视觉或工具栏样式。
