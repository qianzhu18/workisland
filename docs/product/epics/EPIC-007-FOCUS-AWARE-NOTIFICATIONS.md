# EPIC-007: Focus-Aware Notifications

状态：`in-progress`
目标版本：`v0.3.0-beta.2`
来源：Beta 用户反馈、灵动岛遮挡标签栏场景

## 1. 问题

Island 常驻在屏幕顶部时，会遮挡浏览器/编辑器标签栏并持续吸引注意力。用户真正需要的是任务生命周期的两个明确边缘：任务提交后知道任务已接收，任务完成后知道可以回看结果。审批和提问仍然属于阻断式提醒，不能静默丢失。

## 2. 目标

- 默认进入低干扰通知模式，非通知期间隐藏 Island，仅保留可唤回的顶部热区。
- 任务提交和任务完成各显示一次短通知，默认 5 秒后隐藏。
- 审批、提问和错误通知保持可操作，直到用户处理或主动关闭。
- 用户可以在设置中恢复常驻胶囊；桌宠继续作为长期可见的替代展示面。

## 3. 非目标

- 不在本 Epic 中重做 Island 的视觉皮肤。
- 不改变会话状态机、Agent hook 协议或通知音效协议。
- 不把所有后台活动都变成通知。

## 4. 成功证据

| 假设 | 指标/证据 | 门槛 |
| --- | --- | --- |
| 用户不再被常驻 Island 干扰 | 访谈中主动提及遮挡/分心的人数 | 10 人中至少 7 人认为已改善 |
| 关键事件仍可被发现 | 提交/完成通知可见率 | 真实设备 20 次事件 100% 触发 |
| 通知不会成为新的打扰 | 通知后 10 秒内手动关闭或跳转比例 | 不高于 50%，且无 P0 遮挡反馈 |

## 5. 交付拆分

1. `fix/notification-only-default`：默认隐藏、提交/完成 5 秒通知、设置开关和单元测试。
2. `fix/notification-window-macos`：刘海屏、无刘海屏、全屏应用和多显示器实机验证。
3. `docs/beta2-focus-feedback`：更新手册、录制验证证据、Beta 反馈回收。

## 6. 发布门

- `npm run check` 全绿。
- 两台 macOS 设备验证提交、完成、审批、提问和全屏场景。
- 通知结束后窗口回到透明热区，不留下黑色胶囊。
- `v0.3.0-beta.2` Release Notes 写明默认行为变化和恢复常驻的方法。
